# Публикуем ПОДХОД бесплатно

Понадобятся аккаунты GitHub и Supabase. Платный тариф или собственный домен для небольшого учебного проекта не обязательны. Если интерфейс предлагает оплату, убедитесь, что выбраны бесплатная организация и план; лимиты и условия смотрите у провайдера.

## 1. Создать проект

1. Зайдите на https://supabase.com/dashboard и создайте аккаунт (можно через GitHub).
2. Нажмите **New project**, выберите бесплатную организацию, имя проекта, регион и придумайте пароль базы.
3. Сохраните пароль базы у себя. В сайт он не добавляется.
4. Дождитесь готовности проекта.

## 2. Подготовить базу

1. В проекте откройте **SQL Editor → New query**.
2. В GitHub откройте файл [schema.sql](schema.sql), нажмите **Raw** и скопируйте весь SQL.
3. Вставьте в SQL Editor и нажмите **Run**. Должно быть сообщение об успешном выполнении.

Скрипт создаёт таблицу истории, включает RLS (доступ только к своей строке) и функцию атомарного сохранения. Повторный запуск сохраняет существующие записи. Не выключайте RLS и не добавляйте публичный доступ ко всем строкам.

## 3. Подключить сайт

В Supabase найдите **Project URL** и **Publishable key** через **Connect** или **Settings → API Keys** (названия разделов могут меняться). Старый **anon public key** также поддерживается.

В GitHub откройте `config.js`, нажмите карандаш и заполните:

```js
window.PODHOD_CONFIG = {
  backend: 'supabase',
  supabaseUrl: 'https://ВАШ-ПРОЕКТ.supabase.co',
  supabasePublishableKey: 'sb_publishable_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ'
};
```

Сохраните через **Commit changes**. Это публичная конфигурация. **Не используйте пароль базы, secret key (`sb_secret_…`) или `service_role`.**

## 4. Включить GitHub Pages

1. В репозитории `tatatib/pet1` откройте **Settings → Pages**.
2. В **Build and deployment → Source** выберите **GitHub Actions**. Не выбирайте публикацию всего корня ветки: там могут быть локальные служебные файлы.
3. Откройте **Actions → Publish workout tracker → Run workflow → main → Run workflow**. При изменении файлов в main workflow также запускается сам.
4. Дождитесь зелёного результата. Ссылка появится в **Settings → Pages** и в результате deploy. Для этого репозитория ожидаемый адрес — `https://tatatib.github.io/pet1/`, но успешную публикацию нужно подтвердить в GitHub.

Workflow отправляет только HTML/CSS/JavaScript, публичную конфигурацию, SDK и лицензии. SQLite, Python, тесты и секреты в публикацию не включаются.

## 5. Отключить письма

В **Authentication → Sign In / Providers → Email** включите вход по email/паролю, **выключите Confirm email** и сохраните изменения. В некоторых версиях интерфейса настройка подтверждения находится в **Authentication → Settings → Email**. Минимальную длину пароля рекомендуется поставить 10.

Почта используется только как логин. Регистрация сразу открывает аккаунт; писем подтверждения и восстановления пароля сайт не отправляет. Владение адресом не проверяется, поэтому вводите почту внимательно и сохраняйте пароль. SMTP настраивать не требуется.

Перед регистрацией сайт проверяет публичную настройку `mailer_autoconfirm`. Если подтверждение включено или настройку проверить не удалось, регистрационный запрос не отправляется. Это предотвращает случайную отправку писем и повторное исчерпание лимита.

Старые аккаунты, созданные при включённом подтверждении, могут оставаться неподтверждёнными. Владелец проекта может проверить их в **Authentication → Users**. Не удаляйте пользователей или тренировки для обхода ошибки; изменение настройки для новых регистраций не обязательно меняет статус уже созданных аккаунтов.

## 6. Проверить перед отправкой ссылки

1. Зарегистрируйтесь без письма, создайте тренировку и перезагрузите страницу.
2. В другом браузере войдите в тот же аккаунт — история должна появиться.
3. Создайте второй аккаунт — история первого не должна быть видна.
4. Проверьте выход, изменение и удаление записи, экспорт истории.
5. Убедитесь, что регистрация сразу открывает аккаунт и не требует письма. Сохраните пароль — восстановление по почте удалено.

Только после этих проверок считайте сайт готовым для друзей. У бесплатного Supabase бывают паузы из-за неактивности и ограничения ресурсов; сохранить локальную копию истории можно кнопкой «Скачать историю».
