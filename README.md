# ПОДХОД — трекер тренировок с аккаунтами

HTML, CSS, JavaScript и небольшой сервер на Python 3.10+ со встроенной базой SQLite. Внешние библиотеки и сборка не нужны.

## Запуск

```sh
cd /workspace/pet1
python3 server.py
```

Откройте **http://localhost:8000**. Если порт занят: `PORT=8001 python3 server.py` и откройте `http://localhost:8001`.

Для аккаунтов необходим сервер: открытие `index.html` напрямую, Live Server и `python -m http.server` больше не подходят.

## Как пользоваться

1. Нажмите «Регистрация», придумайте уникальный логин и пароль.
2. Выберите дату, упражнения по группам мышц, подходы, повторения, вес и сохраните тренировку.
3. Войдите с тем же аккаунтом через другой браузер по адресу **того же сервера**, чтобы увидеть историю.
4. Если в браузере остались записи первой версии, появится кнопка переноса в аккаунт. Перенос выполняется только по нажатию. При совпадении дат приоритет у серверной записи, оригинал в localStorage остаётся.

Одна тренировка на дату, несколько упражнений, планирование и отметка выполнения, заметки, редактирование, удаление, статистика. Для собственного веса укажите 0 кг. Все подходы одного упражнения используют общий вес и число повторений. Историю можно скачать в JSON, импорт JSON-файла пока не предусмотрен.

Данные каждого аккаунта отделены от других. При одновременном редактировании в нескольких вкладках или устройствах сервер отклоняет сохранение устаревшей версии: проверьте изменения и обновите страницу. Автоматическое обновление открытых вкладок не предусмотрено.

## Хранение и публикация

База по умолчанию — `data/podhod.sqlite3`, она исключена из Git вместе с локальными секретами. Сохраняйте базу на постоянном диске и делайте резервные копии (например, через SQLite backup API). Не публикуйте её в репозитории и не раздавайте папку проекта обычным статическим сервером после появления базы. `server.py` отдаёт только три файла сайта и API.

Для доступа из Интернета нужен хостинг Python с постоянным диском; GitHub Pages поддерживает только статические файлы и для этой версии не подходит. Публикация пока не выполнена.

Настройки через окружение (секретов для локального запуска не требуется):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `8000` | Порт сервера |
| `HOST` | `127.0.0.1` | Интерфейс, `0.0.0.0` для контейнера/хостинга |
| `APP_ORIGIN` | `http://localhost:<PORT>` | Точный внешний адрес сайта, например `https://gym.example.com` |
| `DATABASE_PATH` | `data/podhod.sqlite3` рядом с сервером | Путь к постоянной базе |

Для публикации используйте HTTPS через обратный прокси и задайте `APP_ORIGIN` с `https://`: это также включает флаг Secure для cookie. Не используйте публичный HTTP для передачи паролей. Сервер предназначен для небольшого учебного проекта. В нём пока нет восстановления пароля, подтверждения почты и удаления аккаунта через интерфейс; сохраните логин и пароль. Перед большим публичным запуском стоит перейти на промышленный сервер и готовую систему управления аккаунтами.

Пароли хешируются scrypt с индивидуальной солью; сессии имеют случайные токены (в базе — только хеш), HttpOnly/SameSite cookie и срок 30 дней. Выход отзывает текущую сессию. Запросы изменения требуют совпадения Origin и специального заголовка. Ограничение попыток входа/регистрации действует по IP в памяти процесса и сбрасывается при перезапуске.

## Проверки

```sh
node --check app.js
python3 -m unittest discover -s tests -v
```

Тесты используют отдельную временную базу: проверяют вход, выход, разграничение данных пользователей, конфликты версий, валидацию, запрет запросов с другого сайта и недоступность приватных файлов через HTTP.

## Исходное описание проекта

This is a gym tracker, where you can add your exercises, training time and just track your sport routine :)
