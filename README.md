# ПОДХОД — трекер тренировок

Сайт с календарём, упражнениями по группам мышц, подходами, повторениями, весом и историей. Чёрный фон, оранжевые и лаймовые акценты; поддержка телефонов.

Основной экран разделён пополам: слева запись тренировки, справа календарь. Нажатие на день открывает сохранённые упражнения, вес, подходы и заметки. На телефоне блоки расположены друг под другом.

Нажмите животное рядом с аккаунтом, чтобы выбрать одну из семи аватарок: лиса, кот, медведь, волк, заяц, тигр или панда. Выбор хранится в метаданных аккаунта Supabase, загружать собственные картинки нельзя. Для этой возможности повторно выполнять SQL не нужно. Анимация входа учитывает системную настройку уменьшения движения.

## Бесплатная публикация

**GitHub Pages + Supabase Auth и PostgreSQL**. Посетителям достаточно открыть ссылку и создать аккаунт по почте и паролю; скачивать код и устанавливать Python не нужно.

**[Пошаговая инструкция подключения и публикации →](supabase/SETUP.md)**

Перед публикацией нужно создать проект Supabase, выполнить `supabase/schema.sql`, заполнить публичные параметры в `config.js` и включить GitHub Pages. Пока параметры не заполнены, сайт показывает сообщение настройки, а workflow пропускает публикацию. Наличие файлов в GitHub ещё не означает, что база настроена или сайт опубликован.

Пароль базы, secret key и service_role key нельзя добавлять в код или присылать в чат. В браузер передаются только Project URL и Publishable key (либо старый anon public key). Ключ публичный; доступ к данным ограничивают политики RLS и проверка аккаунта на стороне Supabase.

## Запуск на компьютере

После настройки Supabase:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте `http://localhost:8000`. Самому приложению Python не нужен — это лишь способ раздать статические файлы локально. Для публикации workflow отправляет только файлы сайта, без локальных баз, сервера и тестов.

Старая версия с Python/SQLite сохранена: [инструкция локального режима](LOCAL_SETUP.md).

## Перенос истории

Аккаунты Python/SQLite и Supabase независимы, нужно зарегистрироваться заново. В старом приложении нажмите «Скачать историю», затем в новом аккаунте — «Загрузить историю». Если даты совпадают, остаётся запись из нового аккаунта. Исходная база не удаляется. Браузерная история первой версии также переносится отдельной кнопкой, если открыта на том же адресе браузера.

## Проверки и разработка

Для самого сайта установка npm не требуется: SDK уже собран в `vendor/supabase.js`.

```sh
npm ci --ignore-scripts
npm test
node --check app.js
node --check cloud.js
```

Тесты проверяют обработку ответов Supabase и выполняют настоящую SQL-схему в локальном PostgreSQL (PGlite): изоляцию двух пользователей, запрет анонимного доступа, валидацию и конфликты изменений. Они не заменяют проверку конкретного подключённого проекта Supabase и доставки писем.

Пересборка зафиксированного SDK: `npm run build:vendor`. Исходные лицензии зависимостей находятся в `vendor/THIRD_PARTY_LICENSES.txt`.

На бесплатных тарифах действуют лимиты провайдеров, условия могут меняться; неактивный проект Supabase может приостанавливаться. Экспортируйте историю для резервного копирования. Настройка email-отправителя описана в инструкции, без неё нельзя обещать доставку писем всем пользователям.

Дополнительная браузерная проверка: `python3 tests/browser_cloud.py` (требует Playwright и системный Chromium). Она использует настоящий SDK с локальной имитацией Supabase API, не создаёт реальные аккаунты и проверяет путь `/pet1/`, вход, регистрацию, подтверждение почты, импорт и работу в нескольких браузерах.
